# Retrospective Formats — Reference

Choose the format that fits the team's current needs.

---

## Keep / Stop / Try (Default)

Best for: most situations, simple and effective.

| Column | Question |
|--------|----------|
| **Keep** | What went well that we should continue? |
| **Stop** | What didn't work or caused friction? |
| **Try** | What experiment should we run next sprint? |

Rules:
- Each column needs at least one item
- "Try" items must be specific and time-bound
- Limit to 1-2 experiments per sprint

---

## 4Ls: Liked / Learned / Lacked / Longed For

Best for: sprints with significant learning or frustration.

| Column | Question |
|--------|----------|
| **Liked** | What did you enjoy about this sprint? |
| **Learned** | What new knowledge did you gain? |
| **Lacked** | What was missing that would have helped? |
| **Longed For** | What do you wish you had? |

---

## Sailboat

Best for: visual thinkers, identifying forces at play.

```
   ⛵ (boat = the team)

🏝️ Island (goal)     ⚓ Anchor (holding back)     🌬️ Wind (pushing forward)     🪨 Rocks (risks)
```

| Element | Question |
|---------|----------|
| **Island** | Where are we trying to get? |
| **Wind** | What's pushing us forward? |
| **Anchor** | What's holding us back? |
| **Rocks** | What risks do we see ahead? |

---

## Data-Driven Retro

Best for: when metrics show concerning trends.

Structure:
1. Present sprint metrics with trends
2. Identify top 3 deviations from targets
3. For each deviation: root cause analysis (5 Whys)
4. Propose experiments to address root causes
5. Prioritize: which experiment has highest impact?

---

## Action Item Template

Regardless of format, every retro produces actions:

```markdown
## Action: [specific, measurable action]
- **Owner**: [person responsible]
- **Due**: [date — usually next retro]
- **Success criteria**: [how do we know it worked?]
- **Priority**: [high / medium / low]
```

---

## Facilitation Tips for AI-Assisted Retros

1. **Present data first** — let numbers tell the story before opinions
2. **Ask specific questions** — not "what went wrong?" but "why did cycle time increase 40%?"
3. **One experiment at a time** — changing too many things makes it impossible to learn
4. **Track follow-through** — unfinished actions from last retro are the first topic
5. **Celebrate wins** — start with what went well before addressing problems
